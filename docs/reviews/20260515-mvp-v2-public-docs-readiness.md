## 1. Scope recap

Независимая проверка **согласованности и актуальности** текстов, которые задают историю **MVP v2** для внешнего читателя: корневые `README*.md`, `CHANGELOG.md`, `docs/plans/mvp_v2.md`, `docs/MVP-checklist.md`, фрагмент `docs/GLOSSARY.md`, пакет RFC v2 (`docs/rfc/README-v2-claims-pack.md` и связанные RFC), публично значимые документы под `docs/`, упоминающие экономику v2 / testnet / текущий статус. Цель тикета — подготовка к **первичной публикации** в публичный репозиторий (не финальное ревью спринта).

Заявленные якоря оркестратора: `docs/plans/mvp_v2.md`, `docs/MVP-checklist.md`; RFC 11–14 и WHITE_SPEC пересекаются с экономикой v2 косвенно.

## 2. Requirements fit

**Соответствие цели «единая правдоподобная публичная история MVP v2» — частичное.** Кодовая база и `CHANGELOG` фиксируют ряд решений (например снятие per-block `accrue_marks` из `Chain::seal`, нормализация `marks` / claim), а **корневые README и `docs/pwm-core.md` всё ещё описывают старую модель начисления «каждый блок»**. План `mvp_v2.md` содержит **машинно-неработающие ссылки** (`p:/opt/docker/...`), что делает документ непригодным для читателя с клоном репозитория на другой машине.

`docs/MVP-checklist.md` по духу отражает **фазу 0 / v1 baseline** и не дублирует статусы спринтов v2 из `mvp_v2.md` — для читателя, ищущего «где статус MVP v2», это **пробел навигации**, а не противоречие.

## Приоритетные рекомендации по файлам

### P0 — блокируют уверенную публикацию без исправлений

| Файл | Проблема | Действие |
|------|-----------|----------|
| `README.md` | Утверждение, что счета **накапливают marks каждый блок пропорционально стейку** — противоречит зафиксированному в CHANGELOG (2026-05-06 V2-7) снятию `accrue_marks`/`accrue_marks_v2` из `Chain::seal` и модели claim/genesis marks. | Переписать bullets про marks: зрелость через claim-формулу / stake UX, без «каждый блок»; согласовать с `CHANGELOG` и `docs/rfc/12-claim-maturity-and-state-model.md`. |
| `README-ru.md` | То же, русская формулировка. | Синхронно с английским README. |
| `docs/pwm-core.md` | Раздел «Запечатывание блока» всё ещё перечисляет шаг `accrue_marks(marks_coeff)` после apply — устарело относительно V2-7; вводит разработчиков в заблуждение. | Обновить последовательность seal по текущему коду и политике V2; явно отделить **награду продюсеру** и путь **marks** (claim / policy), без мёртвого шага. |
| `docs/plans/mvp_v2.md` | Десятки ссылок вида `p:/opt/docker/pwm-protocol/...` **не открываются** на машине читателя и не работают на GitHub. | Заменить на **относительные** пути от файла плана (`../../../crates/...` или `../rfc/...` / `../../tasks/...` — по выбранному стилю репо). |
