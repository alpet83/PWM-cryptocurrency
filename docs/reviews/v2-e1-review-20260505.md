# Review: MVP v2 E-1 — core claim / autoclaim / marks / import fee / API

## 1. Scope recap

Слайс заявляет: **единый `marks` в критическом пути burn**, `marks_quota` как зеркало; **BurnMark** с подписанным `burn_purpose` (нормализация/валидация длины и символов); **ClaimTx** (режимы free/paid, проверки якоря/зрелости/дневного free-claim); **auto-claim** при STAKE/UNSTAKE при ненулевой зрелости; **import fee** с нижней границей и зачислением в `fee_pool`; минимальное сопоставление ошибок в **pwmd** (`handlers_tx`). Совпадает с формулировкой тикета и заметками конвейера.

**Артефакты конвейера:** отчёт тест-гейта — `docs/reviews/v2-e1-testing-report-20260505.md` (включая Re-test и Final verdict после fix-итерации).

## 2. Requirements fit

### Ранее зафиксированные блокеры — закрыты (fix + retest)

1. **Precheck vs seal:** приём в mempool использует `Chain::next_apply_ctx` и `State::precheck_apply_with_ctx` с высотой следующего блока и согласованным временем (`handlers_tx`).
2. **Replay / repair / ClickHouse replay:** пути воспроизведения вызывают `apply_tx_with_ctx` с `blk.hdr.height` и `blk.hdr.ts` (`snapshot/io.rs`, `repair.rs`, `ch_http.rs`).
3. **Seal-skip диагностика:** ветка в `lifecycle` использует контекст блока через `apply_tx_with_ctx` и `next_apply_ctx` там, где нужно симулировать следующий seal.

Тестовые якоря после retest (см. testing report): `precheck_tip_uses_next_height_ctx`, `validate_snapshot_replay_uses_block_ctx`, `repair_replay_uses_block_ctx`, `seal_skip_ctx_uses_block_height`, под `clickhouse-snapshot` — CH replay-тесты.

### Остаточные замечания (не блокируют merge E-1)

- **Средне:** грубый fallback маппинга `TxError` → HTTP-код (`_ => "E_SCHEMA_INVALID"`, класс по умолчанию) — как и в первичном ревью; при расширении поверхности ошибок стоит уточнить контракт (`docs/rfc/14` / операторский UX).
- **Низко:** гранулярность зрелости по целым часам — сверить с нормативом RFC 12 на границах времени.
- **Низко / окружение:** `preflight_target_debug.ps1` на хосте тест-гейта не прогнан (PS 5.1 / `pwsh`); на качество самого слайса не указывает, но ограничивает дисковый preflight на Windows.

### Уточнение по телам ошибок

Сборка JSON через `serde_json::json!` с последующей сериализацией строки сообщения устраняет риск поломки JSON от неэкранированных кавычек в `Display` ошибки (ранее отмеченный средний пункт).

## 3. Style and module shape

- Идентификаторы в зоне изменений укладываются в целевую длину (≤ 5 «слов» в `snake_case`).
- Разделение `apply_tx` / `apply_tx_with_ctx` / `precheck_apply_with_ctx` читаемо; док-комментарии у точек входа уместны.
- Снимок (`snapshot/types.rs`): поля счёта для claim-state и сериализация согласованы с `SignedTx`.

## 4. Safety

- Паник в горячих путях в диффе не добавлены; ветки недостаточности средств для import fee присутствуют до мутации баланса получателя.
- Импорт: комиссия списывается после прохождения проверок дубликата и согласованности provenance.
- Доверительные границы: расширение policy prefilter для import fee согласуется с core `MIN_IMPORT_FEE_UNITS`.

## 5. Tests

По отчёту pwm-testing после fix-итерации: `cargo fmt --check`; **pwm-core 96/96**; **pwmd 233+3** (lib+bin); с **`clickhouse-snapshot`** — **237+3**; bench harness snapshot compile-only — OK.
