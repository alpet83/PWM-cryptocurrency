## 1. Термин «matrixchain» в README и в протоколе

В [README.md](../README.md) сказано о «native cryptocurrency using a **matrixchain**». В v0 фиксируем следующее толкование, чтобы у читателя было **общее определение** и опора для diff с whitepaper:

| Уровень | Смысл «матрицы» | Реализация v0 | Цель в whitepaper |
|--------|------------------|---------------|-------------------|
| **Идентификационная ось** | «Строка» матрицы — домен/кластер (`domain_code` + HD-путь); «столбец» — конкретный счёт (`AccountId`). | Один глобальный `AccountId` на 32 байта; домен зашит в первые 16 бит после BLAKE3 (см. WHITE_SPEC). | Кластерные адреса, географический/корпоративный смысл **AABB**, INIT, метаданные. |
| **Исполнительная ось** | «Матрица» исполнения — несколько цепочек или шардов с согласованным финальным состоянием. | **Одна** линейная цепочка блоков (один `Chain`), один глобальный `State`. | Региональный шардинг консенсуса, зоны, арбитры. |
| **Экономическая ось** | Начисления/сжигания по измерениям (стейк × время × зона и т.д.). | Упрощённо: `accrue_marks(coeff)`, `reward_producer`, без зон. | Инфляция, сезонность, IPv4-клайминг, марки с TTL, оффчейн L3. |

**Итог для v0:** *matrixchain* в продуктовом смысле — это **задел по двум осям** (идентификация как «сетка» доменов + будущая сетка цепей), а в коде — **матрица идентичности + одномерная цепь** (single-chain projection). Это сознательное упрощение относительно полного whitepaper.

## 3. Формальная «матрица» v0 (для сравнения с будущими версиями)

**Определение M₀ (MVP):** одна исполняемая цепь `C` и глобальное состояние `S`. Множество счётов `A ⊂ {0,1}^256` (фактически `AccountId`). Отображение идентичности: `(master_seed, i, domain_req) → (sk, pk, AccountId)` при условии из WHITE_SPEC (brute по `i`).

- **Размерность «матрицы» в v0:** по сути `|C| × |A_d|` где `A_d` — счета с префиксом домена `d` в первых 16 битах id; исполнение всё равно **линейно** по высоте `C`.
- **Целевая размерность (whitepaper):** добавляется измерение **зоны консенсуса** `Z` (шард/регион): блоки `B_{z,h}` и правила маршрутизации между `Z`.

Документ фиксирует **разрыв**: v0 = `dim(Z) = 1`; whitepaper допускает `|Z| > 1`.

## 4. Инварианты v0 (что считать «базовым матрикс-чейном» в коде)

1. Один `Chain`, один `State`, один набор валидаторов в genesis (`GenCfg` / `dev_net`).
2. Каждый блок: `prev_hash` связан с предыдущим заголовком; подпись заголовка — Ed25519 продюсера раунда PoA.
3. `state_root` в заголовке — digest от сериализованного `State` после применения всех tx блока, награды и начисления марок (как в реализации `pwm-core`).
4. Любой новый счёт сети вне genesis проходит **INIT** (в т.ч. через stub до первой записи в `accounts`).

Эти четыре пункта — минимальное определение **«базового матрикс-чейна»** в смысле *согласованная одноцепочечная проекция матрицы идентичности*.
