# Sprint V2-5 — marks `u32` и нормализация формулы maturity (коммиты `5033c79`…`54ce229`)

## 1. Scope recap

Тикет `tasks/20260506-v2-sprint5-marks-u32.json`; заявленный охват: снижение типа `Account.marks` с `u128` до `u32`; формула matured `whole_pwm_staked * hours` при `whole_pwm_staked = staked_raw / 1_000_000`; `CLAIM_ALL = u32::MAX`; типы `BurnMark.mark_amount` и `ClaimTx.claim_units` как `u32`; минимальный порог stake для блоковой эмиссии марок `DEF_MARKS_STAKE_MIN = PWM_RAW_SCALE`; миграция snapshot JSON (деление больших legacy-значений на `PWM_RAW_SCALE` с насыщением до `u32::MAX`); синхронизация pwmd API и клиентов (`pwm-cli`, `pwm-tui`); bump `pwmd` **0.1.50 → 0.1.51**; обновление RFC 0011/0012 и связанной белой спеки.

## 2. Requirements fit

1. **`Account.marks` как `u32` в публичном контракте.** В `pwm-core` (`types.rs`, `tx.rs`), pwmd API (`AcctOut.marks`), TUI/CLI пути — согласованно `u32`. Целевой поиск по `crates/**/*.rs` на шаблоны вида `marks:` / `claim_units:` / `mark_amount:` с `u128` — **совпадений не найдено**. CQDS `start_grep` по запросу «marks u128» на дереве `crates/` дал единственное попадание — строка сообщения в `snapshot_roaming.rs`, не поле типа.

2. **`matured_units_available`.** В `state.rs` реализовано как часы целочисленного интервала × `(staked / PWM_RAW_SCALE)` с приведением через `as_marks_u32` (clamp к `u32::MAX`). Тесты `marks_1pwm_1h` (`1_000_000`, 1 ч → **1**) и `marks_sub1pwm_trunc` (`500_000`, 10 ч → **0**) покрывают критерии приёмки.

3. **`CLAIM_ALL = u32::MAX`.** Константа в `tx.rs`; в apply-ветке `Claim` выбор `effective_units` при равенстве с `CLAIM_ALL` даёт «весь matured». Тест `claim_all_sentinel` фиксирует равенство `u32::MAX` и успешный claim на 2 whole PWM за 2 ч (ожидаемые +4 к marks при стартовой 1).

4. **Миграция snapshot JSON.** Тест `marks_snap_migrate` десериализует JSON с `marks: 7000000000000` → **7_000_000** через `de_marks_compat` и `migrate_marks_legacy` (`> u32::MAX` → деление на `PWM_RAW_SCALE`). Ветка `raw <= u32::MAX` сохраняет значение как есть (совместимость с уже «урезанными» или малыми числами) — согласовано с описанием в `issues-report.md` и handoff владельца.

5. **Тесты.** В этой сессии: `cargo test -p pwm-core` — **108 passed, 0 failed, 1 ignored**; `cargo test -p pwm-cli` — **150 passed**; `cargo test -p pwmd` — **237 passed**. Игнорируемый тест один: `snap_keep_imp_replay_guard` в `pwm-core` (bincode + compat-deserializer) — явно помечен и не маскирует падение остального набора.

6. **RFC.** `docs/rfc/12-claim-maturity-and-state-model.md` — формула с `whole_pwm_staked` и `CLAIM_ALL = u32::MAX`. `docs/rfc/11-burn-purpose-and-claim-tx.md` — `claim_units` как `u32` и sentinel.

**Пробелы относительно идеала:** известный техдолг — **bincode**-roundtrip state с `deserialize_with`/`untagged`; не блокирует текущие JSON-snapshot пути, но тест защиты replay-guard отключён до отдельного фикса кодом.

## 4. Safety

Формула truncation по stake снижает скорость роста marks от субцелых PWM-stake; везде по критическим путям используется **saturating** арифметика для `marks`, переполнения `u128` в промежутках maturity не видно при обычных высотах времени. Sentinel `CLAIM_ALL` не конфликтует с реалистичными `claim_units`, так как matured clamp’ится к `u32::MAX` до сравнения. Trust boundary RPC: типы JSON стали компактнее (`u32`), что снижает объём тела ответа без изменения криптоинвариантов.
