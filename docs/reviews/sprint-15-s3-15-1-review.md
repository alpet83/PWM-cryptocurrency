# S15-S3.15.1 — review

## Relay HTTP vs peer TCP

**Вердикт:** исправление корректно — разведение relay HTTP от TCP peer seeds обязательно при модели «rpc+100 = peer listener».

Явный `--transport-relay-http-seed` нужен для нестандартных портов; иначе операторы должны помнить конвенцию **peer_port − 100 = rpc**.

## Красный статус в TUI до шага 1

В `SendStepFlow::from_submit_message` флаг `failed` становится true, если **любая** строка ответа содержит подстроку **`FAIL`** (`lines.iter().any(|line| line.contains("FAIL"))`). Многострочный отчёт с успешным шагом 1–2 и **FAIL** на шаге 3 помечает весь поток как ошибку сразу — из‑за этого блок **status:** в форме Send может быть **красным**, пока пользователь ещё видит только первые строки пошагового вывода.

**Nit (follow-up):** определять «ошибку потока» по завершённому шагу или по последней строке, а не по glob-поиску `FAIL` во всём тексте.
