# Tester guide: типовые ошибки окружения и быстрое восстановление

Этот гайд для тестера и оператора devnet: как быстро распознать типовые проблемы окружения и восстановить рабочее состояние без погружения во внутреннюю реализацию.

Базовое RPC по умолчанию: `http://127.0.0.1:3030`.

## 1) `cargo` не найден / toolchain не установлен

**Symptoms**
- Команда `cargo ...` не запускается.
- Сообщения: `cargo: command not found`, `cargo is not recognized`.

**Check**
- В терминале: `cargo --version`.

**Quick fix**
- Установите Rust toolchain через `rustup` (стандартный installer).
- Полностью закройте и заново откройте терминал.
- Повторите `cargo --version`.

**Retest**
- Выполните `cargo --version`.
- Выполните `cargo run -p pwm-cli --bin pwm -- --help`.

## 2) Порт `3030` занят для `pwmd`

**Symptoms**
- `pwmd` не стартует.
- Ошибка bind/listen на `127.0.0.1:3030`.

**Check**
- PowerShell: `Get-NetTCPConnection -LocalPort 3030 -ErrorAction SilentlyContinue`.
- Если есть результат, порт уже занят.

**Quick fix**
- Остановите процесс, который держит порт `3030`.
- Либо запустите `pwmd` на другом порту: `--listen 127.0.0.1:4040`.
- Если сменили порт, обновите `PWM_RPC` для CLI/TUI.

**Retest**
- Повторно запустите `pwmd`.
- Проверьте head: `Invoke-RestMethod -Uri "http://127.0.0.1:3030/v1/head"` (или ваш новый порт).

## 3) Неверный или устаревший `PWM_RPC`

**Symptoms**
- CLI/TUI отвечает `connection refused`, timeout или ходит в старую ноду.
- После перезапуска окружения данные выглядят "старыми".

**Check**
- PowerShell: `echo $env:PWM_RPC`.
- Проверьте, что URL совпадает с фактическим адресом запущенной ноды.

**Quick fix**
- Установите корректный URL:
  - `$env:PWM_RPC="http://127.0.0.1:3030"`.
- Если используется другой порт, укажите его явно.
- Перезапустите CLI/TUI процесс после изменения переменной.

**Retest**
- `Invoke-RestMethod -Uri "$env:PWM_RPC/v1/head"`.
- Затем повторите целевую CLI/TUI команду.

## 4) Нода не запущена, а CLI/TUI уже стартовали

**Symptoms**
- CLI не отправляет транзакции.
- TUI не обновляет данные, пустой/ошибочный статус подключения.

**Check**
- В отдельном терминале проверьте ответ ноды:
  - `Invoke-RestMethod -Uri "http://127.0.0.1:3030/v1/head"`.

**Quick fix**
- Сначала запустите ноду:
  - `cargo run -p pwmd --bin pwmd`.
- После старта ноды перезапустите CLI/TUI.

**Retest**
- Head endpoint отвечает JSON.
- `pwm-tui` открывается и обновляет экран.

## 5) Неверный формат входных данных (pretty/canonical/domain labels)

**Symptoms**
- CLI возвращает ошибки парсинга аргументов.
- Команды `addr-bruteforce`, `wallet init`, `tx-send`, `tx-burn-mark` падают до отправки.

**Check**
- Убедитесь, что strict pretty имеет вид `pwm1-<label_or_$hex!>-f<flags8hex>-t<tail52hex>`.
- Проверьте, что canonical `pwm1...` передан целиком (без обрезки).
- Для `addr-bruteforce`/`wallet init` проверьте label-only ввод домена (например `CY`), без numeric raw.
- Для user-profile проверьте low-10 policy (`--flags-mask`/`--expected-flags` в пределах `0x03FF`).

**Quick fix**
- Скопируйте адрес заново без лишних символов и без усечения хвоста.
- Для получателя в `tx-send`/`tx-burn-mark` используйте только распознанные non-reserve/non-witness домены.
- Для brute-force/init замените numeric domain на country label (`CY`, `US` и т.п.).
- Если использовался `--expected-result`, допустимо перейти на primary флаг `--expected-flags`.

**Retest**
- Снова выполните команду с теми же шагами.
- Убедитесь, что команда завершается без parse error.

## 6) Ошибки прав/пути при запуске из неверной директории

**Symptoms**
- Команды не видят workspace/crates.
- Сообщения вида "не найден `Cargo.toml`" или access denied/path not found.

**Check**
- Текущая директория: `Get-Location`.
- Убедитесь, что вы находитесь в корне репозитория PWM.

**Quick fix**
- Перейдите в корень репозитория:
  - `cd P:\opt\docker\pwm-protocol`.
- Запускайте команды только из этого каталога (или с корректными путями).
- При проблемах доступа откройте терминал с нужными правами и без блокирующих политик.

**Retest**
- `cargo run -p pwm-cli --bin pwm -- --help`.
- `cargo run -p pwmd --bin pwmd`.

## 7) TUI "ломает" терминал после крэша

**Symptoms**
- После аварийного выхода `pwm-tui` не видно ввод/эхо.
- Курсор/цвета/режим терминала выглядят некорректно.

**Check**
- Закройте текущее окно терминала и откройте новое.
- Проверьте обычную команду (`echo ok`) в новом окне.

**Quick fix**
- Самый быстрый путь: полностью перезапустить терминал.
- Запустите `pwm-tui` заново в чистом новом окне.
- Если проблема повторяется, временно тестируйте CLI-сценарии без TUI и эскалируйте.

**Retest**
- В новом терминале запускается `pwm-tui`.
- Выход по `q`/`F10` возвращает терминал в нормальное состояние.

## 8) Команды выполняются слишком долго / зависают

**Symptoms**
- Нет результата заметно дольше обычного.
- CLI/TUI выглядит "застывшим", нода не отвечает на health-check.

**Check**
- Проверьте head endpoint:
  - `Invoke-RestMethod -Uri "http://127.0.0.1:3030/v1/head"`.
- Проверьте, не завис ли процесс в терминале (нет нового вывода).

**Quick fix**
- Примените watchdog-подход:
  - для CLI: если нет ответа ~15-30 секунд, остановите `Ctrl+C` и перезапустите команду;
  - для TUI: закройте и откройте заново; при автоматизации задайте **`PWM_TUI_RPC_TIMEOUT_MS`** (мс): TUI не будет ждать RPC дольше этого порога (по умолчанию 3000, максимум 120000), в статусе появится `head: timeout` / `accounts: timeout` вместо «вечного» зависания на `send()`;
  - для ноды: перезапустите `pwmd`, затем повторите проверку head.
- Убедитесь, что `PWM_RPC` указывает на живую ноду.
- На Windows для долгоживущих процессов предпочтительнее **Git Bash** или внешний контроль процесса на хосте (например `cq_process_ctl`), чтобы избежать типичных ошибок PowerShell с кавычками/пайпами и реже сталкиваться с проблемами кодировки UTF-8.

**Retest**
- Два последовательных вызова `/v1/head` возвращают ответ без timeout.
- Повторный запуск зависавшей команды проходит в ожидаемое время.

## 9) PowerShell: кавычки, пайпы и UTF-8

**Symptoms**
- Команда «ломается» только в PowerShell, в Git Bash работает.
- Неверная интерпретация `$...`, сложные кавычки в passphrase, обрезанный Unicode в выводе.

**Quick fix**
- Для ручных сценариев переключитесь на **Git Bash** или WSL.
- В PowerShell используйте явные формы кавычек и минимизируйте вложенные `$env:...=...` в одной строке с `cargo run`.
- Для неинтерактивных прогонов рассмотрите Linux-среду (в т.ч. контейнер вроде `mcp-sandbox`, если toolchain там доступен).

## 10) Короткий triage перед эскалацией разработчику

Если проблему не удалось устранить быстрыми шагами, передайте минимально воспроизводимый набор данных:

- точная команда (или 2-3 команды), которую запускали;
- полный текст ошибки (без пересказа);
- shell/OS (`PowerShell`/`cmd`, версия ОС);
- значение `PWM_RPC` и факт, запущен ли `pwmd`;
- время запуска и повторяемость (всегда/иногда);
- короткий лог-фрагмент (5-20 строк) до и после ошибки;
- что уже пробовали из quick fix и результат.

Формат передачи:

```text
Scenario: <кратко>
Command: <точная команда>
Env: OS=<...>, Shell=<...>, PWM_RPC=<...>
Observed: <полный текст ошибки>
Tried: <шаги quick fix>
Result: <не помогло/помогло частично>
```
