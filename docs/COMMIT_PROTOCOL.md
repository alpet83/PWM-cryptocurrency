# Протокол коммитов — PWM-cryptocurrency

> **Для агента:** перед любыми шагами по выкладке или коммиту прочитайте этот файл целиком.  
> Инструмент `git_safe_commit` в MCP к каждому ответу добавляет предупреждение со ссылкой на этот документ.

---

## Две копии дерева

| Копия | Путь | Назначение |
|--------|------|------------|
| Рантайм (деплой) | `P:\opt\docker\PWM-cryptocurrency\` | Рабочие файлы среды; правки делаются здесь |
| Публичное зеркало (git) | `P:\GitHub\PWM-cryptocurrency\` | Канонический репозиторий для публикации |

В зеркале **не** правят файлы вручную как в обычной рабочей копии для разработки: туда попадают изменения только через согласованный поток MCP (см. ниже).

---

## Обязательные правила MCP

1. **Только инструменты MCP** из сервера `gitbash` (`git_safe_commit`, `git_repo_status`, при необходимости `git_list_runtime_deploys`).  
   **Не** вызывать вручную в консоли ни `git …`, ни скрипты подготовки коммита, ни произвольные команды для обхода протокола.

2. Параметр **`public_repo=true`** задаётся **исключительно** для режима **`commit`** и **только** если **`repo_path`** указывает на каталог **внутри** `P:\GitHub\` (публичное зеркало).  
   Для **`dry_run`**, **`apply`** и для локального коммита в рантайме **`public_repo` не указывать** (оставить значение по умолчанию **`false`**).

3. **`dry_run`** и **`apply`** вызываются **только** с **`repo_path`** = рантайм, т.е. `P:\opt\docker\PWM-cryptocurrency\` (или другой корень деплоя под `RUNTIME_PROJECTS_ROOT`).  
   **Не** вызывать `dry_run` / `apply` для путей вида `P:\GitHub\...`.

4. **`commit`** в публичное зеркало: **`repo_path`** = `P:\GitHub\PWM-cryptocurrency\`, **`public_repo=true`**, плюс **`commit_message`** и подтверждение по правилам инструмента.  
   **Локальный коммит** только в рантайме: **`repo_path`** = рантайм, **`mode=commit`**, **`public_repo=false`** (по умолчанию). **Без** предшествующих `dry_run` / `apply`.

5. **Два режима работы (не смешивать):**

   | Режим | Когда | Шаги MCP |
   |--------|--------|----------|
   | **Локальный коммит слайса** | После каждого согласованного слайса в рантайме | `git_safe_commit` **`mode=commit`**, `repo_path`=рантайм, `commit_files` (узко), `confirm` |
   | **Публикация версии** | Только **full MVP closeout** (owner sign-off + sprint-final review) | `dry_run` (рантайм) → согласование → `apply` (рантайм, токен) → `commit` (зеркало, `public_repo=true`) |

   Промежуточные слайсы, soak-волны и chore по тикетам **не** запускают `dry_run`/`apply`.

6. Порядок для выкладки в публичный репозиторий (closeout): **`dry_run`** (рантайм) → согласование с пользователем → **`apply`** (рантайм, с токеном из последнего успешного `dry_run`) → **`commit`** (зеркало, `public_repo=true`).  
   Не пропускать шаги и не менять пути местами.

7. Сообщение коммита: осмысленное, с префиксом вида `feat:` / `fix:` / `refactor:` и кратким описанием.  
   **`git push`** — только если пользователь явно попросил.

---

## Состояние репозитория без консоли

Для просмотра изменений используйте **`git_repo_status`** с нужным **`repo_path`** (рантайм или зеркало) и при необходимости флагами (`short_format`, `porcelain`, `untracked_files` и т.д.).  
**Не** открывать терминал ради `git status`.

---

## Запреты

| Действие | Почему нельзя |
|----------|----------------|
| Ручной `git commit` / `git add` в обход MCP | Обход проверок и протокола |
| Правки файлов в `P:\GitHub\...` «от руки» как в обычном проекте | Нарушение модели двух деревьев |
| `dry_run` / `apply` с путём под `P:\GitHub\` | Неверный контекст: эти режимы только для рантайма |
| `public_repo=true` вне `commit` или вне `P:\GitHub\` | Неверная семантика параметра |
| Включение опций удаления/зеркала без явного согласия пользователя | Риск потери данных на зеркале |
