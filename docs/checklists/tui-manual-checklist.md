# Чек-лист ручной проверки TUI (текущая платформа)

Заполняется оператором: отметьте `[x]` по мере прохождения. Источник сценариев: [tester-guide-cli-tui-scenarios.md](../tester-guide-cli-tui-scenarios.md), актуальные UX-фиксы V2-6…V2-8 и demo JsonFile.

**Окружение:** зафиксируйте `pwmd` commit / тег, `PWM_RPC`, при двух шардах — `PWM_TUI_TARGET_RPC` (если нужен шаг 5 roaming).

---

## A. Запуск и связь с нодой

- [ ] **A1.** TUI стартует с `--rpc` / `PWM_RPC` на живую ноду; `GET /v1/status` → `phase=ready`.
- [ ] **A2.** Выход из TUI штатный (подсказка в UI, например F10 / q — как в вашей сборке).
- [ ] **A3.** При остановленной ноде — понятная ошибка RPC/таймаут, без паники процесса.
- [ ] **A4.** `PWM_TUI_RPC_TIMEOUT_MS` при необходимости увеличен для медленной сети.

---

## B. Кошелёк и таблица аккаунтов

- [ ] **B1.** Разблокировка кошелька (F3 / flow из подсказок); при блокировке F5/F6 не ведут к «тихому» nonce=0.
- [ ] **B2.** Колонка баланса: при `staked > 0` формат компактный **`x/yPWM`** (без двойного «PWM / PWM»).
- [ ] **B3.** Колонка **Marks** отражает значение из RPC после poll.
- [ ] **B4.** Колонка **Staked** (если отображается) согласована с `GET /v1/account` → `staked`.

---

## C. Stake / Unstake (клавиши S / U)

- [ ] **C1.** **S** открывает форму stake; заголовок показывает доступный PWM / текущий staked.
- [ ] **C2.** **U** открывает форму unstake; валидация не превышает застейканное.
- [ ] **C3.** После успешного submit и poll баланс и staked обновляются ожидаемо.

---

## D. Burn marks (F5)

- [ ] **D1.** Подсказка в форме / при блокировке: marks материализуются через **Claim** или **Stake/Unstake**; burn тратит уже materialized marks.
- [ ] **D2.** При выбранном receiver в правой панели beneficiary **pre-filled** и **не редактируется** (как F6).
- [ ] **D3.** F5: после submit claim — статус не «ложный Claimed 0»; есть ветка *submitted / confirmed (+N) / no new marks yet* по poll.
- [ ] **D4.** При `E_FREE_CLAIM_DAILY_LIMIT` — короткое **жёлтое** предупреждение (без длинного blob/trace в футере).
- [ ] **D5.** Burn 1 mark: marks уменьшается после poll; ошибка при wallet locked — явный текст (F3 unlock).
- [ ] **D6.** Purpose / плейсхолдеры `{utc_time}` / `{utc_timestamp}` при необходимости проверены.

---

## E. Send / Roaming (F6)

- [ ] **E1.** F6 send: preflight `init=false` → auto-init при возможности, иначе понятная ошибка.
- [ ] **E2.** Cross-shard: при необходимости задан `PWM_TUI_TARGET_RPC`; шаги handoff доходят до успеха или осмысленной ошибки.
- [ ] **E3.** Шаг 5 verify target: **нет** ложного FAIL из‑за `import_fee` (нетто = amount − fee).

---

## F. Футер и подсказки

- [ ] **F1.** Акселераторы **S** / **U** / **H** в футере с подчёркиванием (если терминал поддерживает).
- [ ] **F2.** История (**H**) открывается, события читаемы.

---

## G. Согласованность с CLI (выборочно)

- [ ] **G1.** Те же операции через `pwm-cli` с тем же `--rpc` дают тот же итог по балансу/marks/nonce (после seal).

---

## Примечания по marks (актуальная модель)

- Genesis может задать начальные marks; **per-block accrue** в консенсусе отключён — не ожидайте рост marks «от одних блоков» без claim/stake-side-effect.
- Для сценария «много блоков — мало matured» сверяйте RFC 12 и поля `staked` / время.
