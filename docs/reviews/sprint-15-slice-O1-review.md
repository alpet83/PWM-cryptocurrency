### 4. Safety

Изменения по смыслу — вынос общих функций и делегирование вызовов; криптографическая логика в коммитах не заявлена как изменённая по протоколу.

В **rpc::blocking_http_client_rpc** при ошибке сборки клиента выполняется однократное предупреждение и откат на дефолтный **reqwest** клиент — это осознанный компромисс по таймаутам (уже отражён в сообщении); для trust boundary RPC это приемлемый паттерн при условии, что операторы понимают возможное расхождение таймаутов в редком случае сбоя builder.

Пути кошелька через **wallet_io** должны сохранять прежнюю семантику относительно CLI (в тикете/ issues указано сохранение обёртки с `DEFAULT_WALLET_OUT_REL` на стороне CLI) — полная верификация без построчного сравнения до/после здесь не выполнялась; риск регрессии путей остаётся зоной внимания **pwm-testing** и ручного смока.
