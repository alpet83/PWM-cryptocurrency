# Review: разделение ролей (genesis / wallet / node / client)

## Что к чему относится

- **`genesis-custom.json`**  
  Это bootstrap-конфиг блокчейна для узла (`pwmd`): стартовое состояние, валидаторы, параметры genesis.  
  Используется при запуске ноды через `--genesis-file` (+ `--genesis-passphrase`).

- **`tmp/genesis.yaml` (wallet)**  
  Это клиентский кошелек для подписи пользовательских транзакций и хранения клиентских данных (accounts/address_book и т.п.).  
  Используется `pwm-cli`/`pwm-tui`, но **не** для запуска `pwmd`.

- **`pwmd` (node service)**  
  Узел сети: API, mempool, sealing, snapshot/state.  
  Работает как серверный процесс и не зависит от wallet-файла в запуске.

- **`pwm-cli` / `pwm-tui` (client apps)**  
  Клиенты к API ноды, подписывают tx и управляют пользовательским сценарием.

## Нужно ли запускать ноду “с кошелька”?

**Нет.**  
Нода запускается из genesis-конфига (или devnet defaults), а не из wallet.

Wallet нужен только клиенту (CLI/TUI) для подписи tx и операторских действий.

## Почему одинаковый MASTER_SEED может путать

Если genesis и wallet были подготовлены из одного seed-источника, это не делает их одной сущностью.  
Это разные роли:
- genesis — состояние/валидаторный bootstrap для узла;
- wallet — клиентский ключевой материал.

Важно: reuse одного root seed для разных ролей увеличивает операционный риск при компрометации секрета, но не меняет саму архитектуру ролей.

## По TUI: “форма закрывается, а прогресс неясен”

Классификация: **ожидаемое текущее поведение + UX gap**.

- Сейчас форма F6 может закрываться после успешного submit, а подробности уходят в историю операций.
- С точки зрения движка это не обязательно ошибка бизнес-логики.
- С точки зрения тестера/оператора это слабая наблюдаемость: не хватает явного финального stage/result прямо в контексте формы.

## Практический порядок запуска (без смешения ролей)

1. Подготовить/выбрать genesis bundle (если custom).  
2. Запустить `pwmd` ноды с согласованным genesis.  
3. Подключить `pwm-cli`/`pwm-tui` к RPC нод.  
4. Использовать wallet в клиенте для подписи и отправки tx.

## Verdict

- **Architecture clarity:** `approve with nits`  
- **TUI UX:** expected behavior, но есть UX-gap по явной фазовой обратной связи для оператора.
