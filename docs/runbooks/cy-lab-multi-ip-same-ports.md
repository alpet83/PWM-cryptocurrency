# CY lab: несколько IP, одинаковые номера портов (KM-Test, 127.0.0.0/8, 169.254.0.0/16)

Краткий runbook для приближения локальной конфигурации к схеме «как на отдельных хостах»: **одинаковые порты** (например `3030` HTTP, `3130` peer TCP) на **разных адресах**.

## Контекст

- Сейчас `cy-cluster-common.ps1` по умолчанию: **три** loopback-адреса **`127.0.0.1`–`127.0.0.3`**, на каждом **HTTP `:3030`** и **peer** на одном номере порта (например **`:13030`** на Windows при конфликте диапазона `313x`).
- Лаунчеры **`cy-cluster-*.ps1`** не перечисляют `--transport-peer-seed` вручную: перед стартом **`Initialize-CyLabPeersFile`** пишет общий **`tmp/cy-lab-peers.yaml`** (multishard `shards` / `$CyDomainHi`, строки `id` + `peer` + `validator`), все узлы получают **`--peers-list`** на этот файл; **pwmd** исключает из сидов свой **`--transport-peer-listen`**.

## Microsoft KM-TEST Loopback

Адаптер **KM-TEST Loopback** даёт дополнительный сетевой интерфейс на Windows. Его часто используют для **изоляции** трафика тестов от основного `127.0.0.1`.

- Для этого адаптера типичны **статические адреса в зоне link-local APIPA**: **`169.254.0.0/16`** (настраивается в свойствах TCP/IPv4 адаптера в `ncpa.cpl`).
- Диапазон **не «заменяет»** loopback `127.0.0.0/8`; это **отдельная** подсеть на виртуальном интерфейсе. Узлы `pwmd` можно слушать на выбранных `169.254.x.y:3030`, `169.254.x.z:3030`, … с **одинаковым** номером порта **3030**, если у каждого процесса **свой IP**.

**Важно:** маршрутизация, брандмауэр и привязка `Hyper-V/WSL` могут влиять на доступность; для чистоты смока проверьте `Test-NetConnection IP -Port 3030` с той же машины.

## 127.0.0.0/8 (привычный loopback)

- По **RFC 1122** весь **`127.0.0.0/8`** относится к loopback.
- **Linux:** часто достаточно добавить алиасы на `lo`, например `ip addr add 127.0.0.2/8 dev lo`, затем `--listen 127.0.0.2:3030`.
- **Windows:** дополнительные `127.0.0.x` иногда работают без настройки, но **менее предсказуемо**, чем на Linux; при сбоях имеет смысл сравнить с **KM-TEST / WSL2 / Docker bridge** или вернуться к **разным портам на одном `127.0.0.1`** (старая схема CY lab в истории репо).

## Что править в репозитории

После назначения IP на адаптере **скопируйте значения** в `cy-cluster-common.ps1`:

- `$CyRpc*`, `$CyPeer*`, `$CyNode*`, `$CyDomainHi` — они же попадают в генерируемый **`tmp/cy-lab-peers.yaml`**; при смене топологии достаточно править **`cy-cluster-common.ps1`**.
- **CORS:** при bind не на классический loopback может понадобиться `PWM_CORS_ORIGINS` — см. помощь `pwmd` и `docs/MVP-checklist.md` §4.
- После корректного завершения **pwmd** может перезаписать **`tmp/cy-lab-peers.yaml`** (persists seeds); каталог **`tmp/`** в `.gitignore` — артефакты лабы не коммитятся.

Автоматический смок [`scripts/cy_cluster_mvp_v2_tail_smoke.ps1`](../../scripts/cy_cluster_mvp_v2_tail_smoke.ps1) по умолчанию опрашивает `http://127.0.0.1:3030`, `:3030` на **`.2`** и **`.3`**. Для **другой схемы** правьте URL в скрипте или **Attach** + свой обёртка с `Invoke-RestMethod`.
