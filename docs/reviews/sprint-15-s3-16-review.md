# S15-S3.16 — review

## Корневая причина (роуминг на source)

Успешный **`relay_import`** доставляет импорт на target, но раньше не обновлял **`RoamingPool`** на source. Инвариант «импорт завершён» для source-снимка и UI должен фиксироваться после подтверждённой доставки на target — добавлены **`mark_imported_by_export_id`**, flow trace и сохранение снапшота на source.

## Логи

- **`sealed height`**: вывод раз в **10** блоков (и при высоте **1**), чтобы не забивать консоль на быстром seal loop.
- **`peer account views merged`**: лог только если **`changed`** для данного `source_node_id` **изменился** относительно последнего залогированного значения (подавление повторяющихся `count=1`).

## Риски

- Дублирующее сохранение снапшота при частых импортах — приемлемо для MVP; при нагрузке можно батчить.
- **`save_snapshot`** сделан **`pub(crate)`** для использования из `relay` без циклического импорта `api`.

## Вердикт

**APPROVE** для scope слайса. Если баланс на target по-прежнему не сходится при живой проверке — смотреть сумму/комиссию в теле Import и гейты инициализации получателя на target (отдельный инцидент).
