# Wave A — диагноз расхождения `tip_hash` между same-shard нодами

**Тикет:** `tasks/20260508-v2-slice6-hotfix-tip-hash-divergence.json`  
**Цель:** отделить шум harness от реального расхождения цепочки и дать минимальный путь фикса.

---

## Recap охвата

- Скрипт: `scripts/wave_a_same_shard_stop.py`.
- После остановки `tip_hash` берётся **только из** `epochs/pwm-epochs-manifest.json` (`man1["tip_hash"]` vs `man2["tip_hash"]`). Живой `/v1/head` в финальном отчёте не используется (во время прогона высота читается из `/v1/head`).
- В `pwmd` манифест обновляется при дописи epoch: `tip_hash = hex(hdr_hash(blk.hdr))` (`crates/pwmd/src/snapshot/incremental.rs`). `/v1/head` отдаёт тот же `chain.tip_hash()` (`crates/pwmd/src/api/handlers_status.rs`).
- `hdr_hash` хэширует **полный** `BlockHdr` через bincode (`crates/pwm-core/src/block.rs`), включая **`ts`** и **`sig`**.
- Время блока задаётся `Chain::next_apply_ctx()` как `SystemTime::now().as_secs()` (`crates/pwm-core/src/chain.rs`); подпись зависит от preimage с `ts`.

## Ответ по пунктам

### 1) Наследие: false-positive harness или реальное расхождение?

**Это не «ложное срабатывание» сравнения:** harness читает ровно тот `tip_hash`, который записан в манифест и согласован с логикой `hdr_hash` последнего зафиксированного блока на данной ноде.

При **`tip_hash_equal=false`** между нодами означает: **на диске у них зафиксированы разные заголовки кончика** (разные байты заголовка ⇒ разный `hdr_hash`). Это **реальное расхождение идентичности блока на tip**, а не ошибка сравнения полей.

Важно: это **не обязательно** расхождение **применённого состояния** по проверяемым аккаунтам: harness сравнивает только `balance_pwm` / `nonce` / `initialized`. Теоретически возможен сценарий «одинаковое подмножество аккаунтов, разный заголовок» (например, разный `ts`/`sig` при тех же `tx_root`/`state_root`), но по текущей модели PoA это **недетерминизм цепочки на уровне заголовка** и для MVP/testnet **недопустимый** сигнал, если цель — одна каноническая цепь.

**Корневая причина по коду:** независимый wall-clock **`ts`** (и производная от него подпись) при локальном seal или при разных физических блоках на одной высоте до полной конвергенции gossip.

### 2) Если считали бы «ложным» — минимальный fix harness/criteria

Сейчас **ослаблено** ограничение по epoch-файлу: есть проверка **имени** последнего epoch-файла и SHA256 содержимого в отчёте (`last_epoch_hash_equal`), но **exit code при `last_epoch_hash_equal=false` не валится** — в отличие от нарратива Phase A в ревью слайса. Минимальные действия со стороны критериев Wave A:

- **Жёстко фейлить**, если `last_epoch_hash_equal` — false (байтово одинаковый последний `block_e*.json`).
- Тогда при идентичных цепочках **`tip_hash` совпадёт автоматически** (последняя строка JSONL та же ⇒ тот же `hdr_hash`). Поле `tip_hash_equal` станет **избыточным** как gate, останется диагностикой/manifest self-check.
- Дополнительно (низкий приоритет): проверка согласованности `manifest.tip_hash` с хвостовой строкой epoch (ловит гонки/баги записи манифеста); при **`last_epoch_hash_equal=true` и несовпадении `tip_hash` с tail** — это уже **баг persist**, а не «дрейф сети».

### 3) Если реальное расхождение — минимальный hotfix-путь для MVP (`pwm-coding`)

**Цель:** одна и та же байтовая цепь на всех узлах same-shard при одинаковом потоке tx.

Приоритет (от более узкого к более широкому):

1. **Детерминированный `ts` для seal (testnet / флаг сборки или cfg):** например `ts = genesis_ts + k * height` или фиксированный виртуальный clock из состояния, **без** `SystemTime::now()` на критическом пути блока — тогда два узла не расходятся из-за времени даже при одинаковом наборе tx. (Осторожно: policy v2 держит сезон через `season_ppm(ts)` — нужно сохранить согласованную семантику или ограничить фикс тестовым профилем.)
2. **Единственный локальный seal на высоту:** не допускать независимого seal второй ноды, пока не применён блок от текущего proposer (уже ближе к продуктовой семантике PoA); peer применяет **тот же** сериализованный блок, что и источник.
3. **Ужесточение приёма sync:** отклонять альтернативный заголовок на той же высоте с тем же `state_root`/`tx_root`, если уже есть выбранный canonical tip (если политика выбора определена).

Минимальный **практический** шаг для harness + MVP: **(1) в тестовом профиле** + **(2)** не нарушать текущие prod-mainnet инварианты.

## Рекомендация для `pwm-coding` (одна фраза)

Ввести **детерминированный источник `ts` для seal** в testnet/harness (или глобально за фичефлагом) и/или **запрет параллельного локального seal** не-пропоузером; параллельно в Wave A **сделать FAIL при `last_epoch_hash_equal=false`**, чтобы не маскировать расхождение цепочки «зелёным» exit code.
